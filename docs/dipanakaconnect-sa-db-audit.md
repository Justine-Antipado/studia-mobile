# Di pa naka-connect sa DB: audit ng `studia-mobile`

> **Update 2026-11-23:** tinanggal na ang buong mock layer ng mobile. Tapos na ang #1, #7, #8 at ang mock-parts ng #2 at #3. Ang natitira ay nasa seksyon "Status pagkatapos tanggalin ang mock" sa dulo.

Petsa ng audit: 2026-11-23. Sakop: `studia-mobile/src`, ikinumpara sa `supabase/migrations/` (001 hanggang 020), `supabase/functions/` at `studia-api/`.

## Buod

Karamihan ng app ay **naka-connect na** sa Supabase kapag `EXPO_PUBLIC_DATA_SOURCE=remote`. Bawat repository sa `features/*/data/` ay may `*-remote.ts`. Ang natitirang mock o local-only ay ito:

| # | Bahagi | Status | Priority |
|---|---|---|---|
| 1 | EAS builds (default sa mock) | Hindi naka-remote | Mataas |
| 2 | AI Assistant chat (student at instructor) | 100% mock | Mataas |
| 3 | AI Quiz Generator (instructor) | 100% mock | Mataas |
| 4 | AI summary regenerate (student lesson) | Disabled, walang server | Katamtaman |
| 5 | AI processing ng materials (transcript, objectives, summary) | Walang worker | Katamtaman |
| 6 | Profile photo | Sa device lang | Katamtaman |
| 7 | `class-directory.ts` (student at instructor) | Natitirang mock code | Mababa |
| 8 | Oras ng app (`mockNow`) | Mock clock ang gamit kahit remote | Mababa |
| 9 | Query cache | In-memory lang | Mababa |
| 10 | Mga table sa DB na walang gumagamit sa mobile | Orphan | Impormasyon |

## 1. EAS builds: default pa rin sa mock (Mataas)

- `core/config/data-source.ts` ay nagde-default sa `mock` kapag walang `EXPO_PUBLIC_DATA_SOURCE=remote`.
- Ang `remote` ay naka-set lang sa `.env.local`, na **gitignored** (kinumpirma ng `git check-ignore`). Hindi ito kasama sa EAS build.
- Ang `eas.json` (development, preview, production) ay may Google client IDs lang. **Wala** ang `EXPO_PUBLIC_DATA_SOURCE`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` at `EXPO_PUBLIC_API_URL`.
- Resulta: gagana lang sa database ang `npx expo start` sa makina mo. Ang APK o IPA mula sa EAS ay babalik sa in-memory mock data at lalabas ang "Demo data" pill.

**Ayusin:** idagdag ang apat na env var sa `env` ng bawat profile sa `eas.json`, o gumamit ng `eas env:create`. Public values ang URL at anon key. Huwag ilagay ang service-role key.

## 2. AI Assistant chat: mock (Mataas)

- `features/shared-screens/screens/ai-assistant-screen.tsx` ay direktang nag-import ng `CHAT_CONFIG` at `mockReply` mula sa `core/data/mock/mock-data.ts`. May `TODO(refactor)` din sa file.
- Ang sagot ay galing sa local na function, hindi sa AI at hindi sa DB. Walang `ai-service` o repository layer.
- Nasa DB na ang `ai_chat_messages` at `ai_requests` (migration 006). Walang gumagamit sa mobile.
- Sinasabi mismo ng `data-source.ts` na ito ang tanging domain na hindi remote.

**Kailangan:** `ai-chat-repository` (mock at remote), endpoint sa `studia-api` o Edge Function na tumatawag sa AI provider sa server (hindi sa app), at pag-save ng mensahe sa `ai_chat_messages`. Dapat enforced sa server ang quota gamit ang `ai_requests`.

## 3. AI Quiz Generator: mock (Mataas)

- `features/instructor/logic/ai-quiz-generator.ts` → `generateQuiz()` ay may `setTimeout(900)` at gumagawa ng "Sample answer A/B/C/D about {topic}".
- Walang `isRemote` branch. Kahit remote mode, mock pa rin ang lumalabas, at ang mga placeholder na tanong ay puwedeng ma-save bilang totoong quiz sa DB gamit ang `save_quiz`.
- Ginagamit sa `ai-quiz-screen.tsx`.

**Kailangan:** server endpoint na gumagawa ng mga tanong (Bloom level at difficulty) at nagre-return ng `QuizQuestion[]`. Panatilihin ang signature. Habang wala pa, i-disable o lagyan ng "Coming soon" ang screen kapag remote.

## 4. Regenerate AI summary: disabled (Katamtaman)

- `features/student/data/lessons-remote.ts` → `regenerateSummary()` ay laging nagre-return ng error: "AI summaries are generated by the server and can't be regenerated from the app yet."
- Nasa DB na ang `material_summaries` (`mode`, `tldr`, `bullets`, `regen_count`) at binabasa na ito ng app. Wala pang server na nagsusulat o nagre-regenerate.
- Ang mock ay may `MAX_SUMMARY_REGENS`. Wala pang katumbas na limit sa server.

**Kailangan:** RPC o endpoint para sa regenerate na nagtatakda ng limit sa `regen_count`.

## 5. AI processing ng materials: walang worker (Katamtaman)

- Sinasabi ng `features/instructor/data/materials-remote.ts`: "There is no AI worker yet".
- Sa mock, may pipeline (`mock-materials.ts`) na gumagawa ng transcript, objectives at summary. Sa remote, walang gumagawa nito.
- Pansamantalang solusyon ay manual: `provideTranscript()` → RPC `set_material_transcript`. Ang `material_objectives` at `material_summaries` ay walang sumusulat.
- Resulta: ang mga lesson ng student ay walang objectives at summary.

**Kailangan:** background job (Edge Function o queue) na gumagawa ng objectives at summary, saka nag-a-update ng `materials.processing`.

## 6. Profile photo: sa device lang (Katamtaman)

- `features/shared-screens/data/profile-remote.ts` → `setAvatar()` at `loadAvatar()` ay gumagamit ng `AsyncStorage` (key: `studia.avatar.<email>`).
- Hindi ito naka-upload kahit handa na ang `users.avatar_path`, ang `avatars` bucket (migration 015) at ang `studia-api/api/me/avatar.ts`.
- Resulta: nawawala ang litrato kapag nag-reinstall o nag-login sa ibang device, at hindi ito nakikita ng ibang user.

**Ayusin:** tawagin ang `POST` at `DELETE /api/me/avatar`, at gumamit ng signed URL sa pagbasa.

## 7. `class-directory.ts`: natitirang mock code (Mababa)

- `features/student/data/class-directory.ts` at `features/instructor/data/class-directory.ts` ay nagbabasa mula sa `mockDb`.
- Ang student version ay ginagamit lang (`classmatesOf`) ng `MockClassRepository`. Ang remote ay gumagamit ng RPC `class_classmates`.
- Ang instructor version ay walang nag-iimport sa labas ng sarili nitong file, kaya dead code.
- Ang module-level `CLASS_DIRECTORY` ay tumatakbo pa rin sa startup kahit remote mode.

**Ayusin:** burahin ang instructor version. Ilipat ang student version sa mock section.

## 8. `mockNow` bilang oras ng app (Mababa)

- `shared/utils/format.ts` (`isOverdue`, `timeAgo`, `dueLabel`) at `features/student/logic/task-filters.ts` (`isDueToday`) ay gumagamit ng `mockNow()` mula sa `core/data/mock/mock-clock`.
- Kung may offset ang mock clock, mali ang "overdue" at "due today" kahit totoong DB data.
- Hindi ko pa nasuri kung ano ang ginagawa ng `mockNow()` sa remote mode. I-verify at palitan ng `Date.now()` kung may offset.

## 9. Query cache: in-memory lang (Mababa)

- `core/data/cache/cache-store.ts` ay `MemoryCacheStore` lang. Walang persistence, kaya bawat cold start ay may bagong fetch at walang offline na data.
- Hindi bug. Opsyonal na improvement.

## Kumpirmadong naka-connect na

Auth (`remote-auth-service`), classes (student at instructor), announcements at comments, assignments at submissions (kasama ang file upload at edit submission), quizzes (student at instructor, `save_quiz`), submissions at grading, gradebook, analytics (`instructor_analytics()` RPC), students roster, materials (upload at video link), lessons at material views, planner, tasks at overrides, notifications (kasama ang Realtime at push tokens), profile edit at password change (via `studia-api`).

## Mungkahing pagkakasunod

1. **#1** (EAS env): mabilis at pinakamalaki ang epekto.
2. **#3** at **#2**: i-disable muna ang mock AI sa remote mode, saka gawin ang server endpoint.
3. **#6** (avatar): handa na ang API at bucket, mobile na lang ang kulang.
4. **#5** at **#4**: AI worker para sa materials.
5. **#7**, **#8**, **#9**: cleanup.

## Paano sinuri

Binasa ang `data-source.ts`, bawat `*-repository.ts` at `*-remote.ts`, ang `core/data/supabase/*`, ang mga screen na direktang nag-iimport ng `core/data/mock`, ang `eas.json` at `.env.*`, ang mga migration at ang `studia-api`. Static code review lang ito. Walang pinatakbong app o query sa live DB, kaya hindi nito nakukumpirma kung tama ang RLS policies o kung nakadeploy ang mga migration.

## Update: AI na ang naka-connect (2026-11-23)

Nagawa na ang #2, #3, #4 at #5 gamit ang free AI API (default: Google Gemini, OpenAI-compatible kaya puwedeng palitan ng Groq o OpenRouter sa env lang).

| Feature | Endpoint (`studia-api`) | Saan nasusulat |
|---|---|---|
| AI Assistant chat | `POST /api/ai/chat` | `ai_chat_messages`, `ai_requests` |
| AI Quiz Generator | `POST /api/ai/quiz` (instructor lang) | `ai_requests`. Ang quiz ay nase-save sa normal na `save_quiz` |
| AI summary at regenerate | `POST /api/ai/summarize` | `material_summaries`, `material_objectives`, `ai_requests` |

- Ang API key ay nasa Vercel env lang (`AI_API_KEY`). Wala ito sa mobile app.
- Limit bawat user kada oras: chat 40, quiz 12, summary 20. Ang regenerate ng student ay hanggang 3 bawat lesson.
- Ang summary ay gawa sa transcript. Kapag nag-paste ng transcript ang instructor, awtomatikong gagawa ng summary at key objectives. Ang PDF at slides na walang transcript ay wala pang AI text.
- Kailangan i-deploy ang `studia-api` at i-set ang `AI_API_KEY` bago ito gumana.
